# Aspectori search and product strategy — 18 October 2026

## Decision

Lead with a free, understandable birth chart and PDF; compete on visible calculation evidence, missing-time honesty and house comparison. Dedicated calculators should answer distinct tasks. Educational pages should explain those tasks using examples and sources. Do not describe the product as perfect or the market leader without comparative evidence.

The working audience is English-speaking users, initially a US/UK hypothesis. The owner has not supplied a public production domain, Search Console history, target-country data or keyword-tool exports. This work improves the local product; it does not establish a live deployment, indexing status, search volumes or rankings.

## Research delivered and how to read it

- [Keyword map](keyword-research-2026-10-18.csv): **518 distinct terms**. Each has a cluster, intent, target URL where appropriate, priority, product readiness, evidence label and recommended action.
- **18 searched queries**: exact query strings evaluated through English web search. [Evidence](search-evidence-2026-10-18.json) preserves the date and up to five result titles/URLs per query. These are not a location-controlled Google ranking sample and do not demonstrate volume.
- **260 inferred variants**: related ways of expressing an intent, derived from the product, competitor vocabulary and topic analysis. They were not all searched separately.
- **240 enumerated hypotheses**: 144 existing Sun/Moon combinations, 36 possible placement-guide subjects and 60 celebrity/name combinations. Enumeration is a coverage check, not evidence of demand.
- Priority distribution: **128 P0**, **58 P1**, **306 P2**, **26 P3**. These are term counts, not proposed page counts. Many terms map to one page.
- [Keyword Planner import](keyword-planner-import.csv): the 186 P0/P1 terms for a first demand-validation pass.
- [Competitor review](competitor-review-2026-10-18.md): 12 first-party product comparisons and explicit product gaps.

Monthly volume, keyword difficulty and CPC are intentionally empty. “Source” identifies an evidence file or a related topic/product reference; it does not imply the exact phrase appeared there. Do not publish any inferred or enumerated phrase as a measured search query. P0 means immediate relevance and current product fit, not proven low competition.

To validate volume, import the priority terms into Google Keyword Planner twice: English/United States and English/United Kingdom, keeping date range and network settings explicit. Export average searches, seasonality and advertising competition separately by country. Ads competition is not organic ranking difficulty. Record organic competition qualitatively from actual result pages until an SEO-tool dataset is available. [Google Keyword Planner guidance](https://support.google.com/google-ads/answer/7337243) and [historical-metrics API documentation](https://developers.google.com/google-ads/api/docs/keyword-planning/generate-historical-metrics).

## Changes implemented in this review

- Free PDF export now works directly from a chart. It preserves the selected house system, includes native selectable text and an embedded Unicode font, and has a print fallback. The offer requires no email, account or payment. A failed year calculation permits a natal-only download with an explicit note.
- Five task-specific calculators, four original supporting guides, an index for each collection, and a public report landing page.
- Expanded synastry response with all qualifying contacts; the original three highlights are preserved.
- Crawlable category pagination at 96 people per page replaces the truncated category path to the collection. Sitemap entries and category counts follow the same pagination model.
- Self-canonical metadata for new pages; real 404s for unknown dynamic tool/guide/category-page routes; page-one pagination redirects to its base category.
- Home, header and footer links connect the tools, guides and PDF offer. New information is available in server-rendered HTML; calculations require JavaScript.
- Personalized `/report` is `noindex` and absent from the sitemap. It is no longer blocked by robots.txt, so crawlers can read that instruction. Birth details remain in URL fragments and API bodies; no birth-data analytics were added.
- Corrected a celebrity FAQ that had described a timed Moon position as a whole-day result.
- Removed the meta-keywords field; Google does not use it for ranking. Scoped calculator application schema to relevant pages instead of all pages.

[Google’s noindex documentation](https://developers.google.com/search/docs/crawling-indexing/block-indexing) explains why robots.txt must allow the instruction to be read. [Supported metadata documentation](https://developers.google.com/search/docs/crawling-indexing/special-tags) confirms the lack of a meta-keywords ranking effect. These changes remove technical problems; they do not guarantee indexing.

## What to avoid

Do not add hundreds of thin pages simply because the keyword CSV contains them. Existing combination and celebrity templates need distinct utility, reliable source data and a usable index. Google treats scaled content produced primarily to manipulate rankings and doorway pages as spam regardless of production method. [Search spam policies](https://developers.google.com/search/docs/essentials/spam-policies).

Do not promise FAQ rich results: Google generally limits those displays to authoritative health and government sites. Existing FAQ markup can describe visible answers, but is not an astrology ranking strategy. [Google’s FAQ rich-result update](https://developers.google.com/search/blog/2023/08/howto-faq-changes).

Do not target Vedic/sidereal charts, astrocartography, composite charts, full transit calendars or solar returns with pages implying that we provide them. Their 26 backlog terms are discovery candidates; they need a real product and calculation validation first. Celebrity Rising queries must receive an honest “unknown” where the time is not recorded.

## Measurement plan

Use Search Console for impressions, clicks, CTR, query/page/country breakdown and indexing reports. Separate brand queries from discovery queries. Use field Core Web Vitals when available; local browser checks are not field performance results.

If product analytics are later introduced, record only minimal events such as `chart_calculation_succeeded`, `pdf_export_succeeded`, `pdf_export_failed` and `guide_to_calculator`. Do not capture birth date, birth time, coordinates, names, API bodies or URL fragments. Choose consent and retention behavior for the actual deployment before adding analytics. No analytics SDK or tracking was added in this change.

Define the funnel as landing visit → valid chart result → useful next action (PDF or deeper exploration). Measure error and abandonment rates by step. Set improvement targets after a real baseline; traffic alone does not establish a better product.
